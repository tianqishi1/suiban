# 「随办」产品设计方案与技术实现方案

版本 v0.9（评审稿）｜2026-11-24｜基于开源项目 Mika（Apache-2.0）二次开发

## 0. 摘要

- 定位：面向业务用户的移动端 AI 工作助手，「屏幕顾问 + 手机执行器」双模式。
- 首发滩头：私域销售/运营；扩张路线：跨境卖家、HR/猎头、实体小店主。
- 形态：安卓 APK（主产品）+ 免安装小程序（获客漏斗）+ 团队 Web 控制台。
- 技术策略：薄 fork + 厚插件；模型托管于百炼；云端自建账号/计费/审计/技能分发。
- 节奏：M0 验证 2 周 → M1 MVP 6–8 周 → M2 团队版 4–6 周。
- 关键目标：建议采纳率 ≥40%；执行成功率 ≥85%；顾问 ≤0.02 元/次；执行 ≤0.3 元/任务。

# 第一部分 产品设计方案

## 1. 定位与目标用户

一句话定位：看懂你正在看的屏幕，给你建议；你点头后，替你把事办完。

与 Mika 的差异：

| 维度 | Mika（上游） | 随办（本产品） |
|---|---|---|
| 目标用户 | 开发者/极客 | 销售、客服、运营等业务用户 |
| 开箱体验 | 自配模型 Key、自写技能 | 场景包开箱即用，模型托管 |
| 核心交互 | 下任务→等结果 | 建议卡片→一键委托 |
| 交付 | 开源 APK | 订阅制产品 + 团队版 |

滩头画像（私域运营者）：每天微信/企微高频客户对话；手工把订单/客户信息录表；需要盯竞对价格与评价。付费意愿来自「省时间 + 不漏单」。

双模式设计（产品灵魂）：
- 顾问模式（默认）：只识别 + 建议，最终动作由人完成。合规、省 token、建立信任。
- 执行模式（按场景开启）：隐藏屏代操作，保留人工接管与敏感动作闸门。
- 微信场景永远默认顾问（只给建议不代发），企微/邮件/公开平台可开执行。

## 2. 产品形态与用户旅程

三端：安卓 APK（核心）；轻量小程序（手动分享截图→建议，免安装试用漏斗）；团队 Web 控制台（M2）。

首次使用（目标 10 分钟）：
1. 官网下载 APK 安装（无障碍类应用商店上架难，初期官网/企业渠道分发）。
2. 手机号注册登录 → 自动下发托管模型配置（用户不接触 API Key）。
3. 设置向导：悬浮窗权限 → 无线调试配对 → 无障碍自动开启（复用 Mika 向导，配对后自动开无障碍，规避「受限制的设置」拦截）。
4. 选择场景包（默认开启「消息回复顾问」）。

日常使用：
- 悬浮胶囊常驻 → 双击 → 1–3 秒出建议卡片（3 条候选回复/抽取结果）→ 复制、编辑或委托发送。
- 任务中心：委托的任务后台跑，进度时间线可回看，敏感步骤弹确认，可随时接管。
- 巡检类：后台自动触发，报告推企微/飞书。

已知摩擦与对策：无线调试配对是最大流失点（向导分步引导 + 电脑 USB 一键激活兜底）；部分 ROM 重启需重配对（保活与自动重连，Mika 已有基础）；团队版走工作手机批量部署。

## 3. 功能设计

MVP 三个场景包：

| 场景包 | 触发 | 输入 | 输出 | 模式 |
|---|---|---|---|---|
| 消息回复顾问 | 双击胶囊 | 当前聊天屏（截图+控件树） | 3 条候选回复（语气/长度可配）+ 一键复制/委托发送 | 顾问为主 |
| 屏幕信息抽取 | 胶囊长按或圈选 | 订单/商品/名片/聊天页 | 结构化字段 → 云端表格/导出 xlsx/写 CRM | 顾问+执行 |
| 定时巡检播报 | 时间/通知触发 | 竞对价格、店铺评价、库存 | 摘要报告 → 企微/飞书群 | 执行 |

平台功能：账号与订阅；场景包开关与配置；任务中心与过程回看；token 预算与用量看板；团队管理/审计/技能分发（M2）。

优先级：P0 = 顾问卡片、场景包 1、托管模型登录、设置向导、预算熔断；P1 = 场景包 2/3、用量看板、小程序轻量版；P2 = 团队控制台、审计、技能市场、私有部署。

## 4. 交互与 UI 要点

- 建议卡片：结构化渲染（理解摘要 + 候选列表 + 动作按钮），不是纯文本聊天；候选可滑动切换、长按编辑。
- 执行时间线：每步一行（做了什么、看到什么、结果），失败步骤高亮并给接管入口（复用 Mika takeover）。
- 确认闸门：花钱/发消息/删除弹卡片确认，付款永远人工（保留上游询问模式）。
- 胶囊状态：空闲/思考/执行中/等待确认，四态可区分。

## 5. 商业模式与定价（示意，M0 后校准）

| 档位 | 定价 | 权益 |
|---|---|---|
| 免费 | 0 | 顾问 20 次/天，单场景包 |
| 专业版 | ¥39/月 | 顾问公平使用不限量 + 执行 300 次/月 + 全部场景包 |
| 团队版 | ¥99/席/月 | 控制台、审计、技能分发、用量池 |
| 企业版 | 商务 | 私有部署、数据不出域 |

成本与毛利：顾问单次约 3–5k token（视觉模型），≈0.01–0.02 元；执行任务 10–30 轮、压缩后累计 50–150k token，≈0.1–0.3 元。专业版月成本约 ¥15–25，毛利约 40–60%。预算熔断保证最坏情况不穿底。

## 6. 合规与风控

- 无障碍权限用途明确披露；用户协议界定「用户委托、用户负责」。
- 付款/验证码/密码永远人工接管；发消息、删除默认二次确认。
- 微信只顾问不代发；不做群发营销、不碰投资建议/医疗诊断/游戏自动化。
- 敏感字段（手机号/金额/身份证）上传前脱敏；审计日志全量留痕。
- Apache-2.0：保留 LICENSE/NOTICE，产品换名换包名。

## 7. 指标体系

- 北极星：建议采纳率（顾问）≥40%。
- 执行任务成功率 ≥85%；顾问 P95 时延 ≤3s；执行 P95 ≤3min。
- 单任务成本达标率；D7 留存 ≥30%；设置向导完成率 ≥70%。

## 8. 版本路线图

| 阶段 | 周期 | 交付 | 退出标准 |
|---|---|---|---|
| M0 验证 | 2 周 | 目标机型兼容实测 + 3 场景 PoC + 成本基线 | 成功率/成本达标，否则止损 |
| M1 MVP | 6–8 周 | fork 换壳 + 三场景包 + 建议卡片 + 托管模型 + 个人版内测 | 50 名种子用户周活 ≥3 天 |
| M2 团队版 | 4–6 周 | 控制台/审计/技能分发 + 企微飞书集成 + 计费 | 3 家付费团队 |
| M3 生态 | 持续 | 场景包市场（跨境/HR/小店主），评估独立演进 | — |

# 第二部分 技术实现方案

## 1. 总体架构

```
┌─ 模型层（百炼托管）────────────────────────────┐
│ qwen3-max 主模型 │ qwen-vl-plus 看图 │ qwen-flash 轻量 │
└──────────────────▲───────────────────────────┘
                   │ OpenAI 兼容接口（设备不持主 Key）
┌─ 云端层（自建）──┴───────────────────────────┐
│ 模型网关(计量/限流/短期令牌) │ 账号计费 │ 技能分发 │
│ 审计存储 │ 抽取表格服务 │ MCP 桥(企微/飞书/CRM)   │
└──────────────────▲───────────────────────────┘
                   │ HTTPS/WSS（设备主动外连）+ MCP/CLI（指挥手机）
┌─ 手机端（Mika fork）┴────────────────────────┐
│ 建议卡片(新) │ 场景包(skills/plugins) │ 预算熔断(改) │
│ 保留: AgentLoop · screen · safety · cap/phone ·    │
│       learn/replay · proactive · mcp              │
└──────────────────────────────────────────────┘
```

两条数据流：
- 顾问流（轻）：胶囊双击 → 截图+控件树 → 网关单次 VLM 调用 → 结构化 JSON → 建议卡片。不进 AgentLoop。
- 执行流（重）：委托 → AgentLoop（观察→决策→动作→校验）→ 安全闸门 → 结果/审计上传。

## 2. 手机端二次开发（模块级）

Fork 策略：薄 fork + 厚插件。core 只改路由/提示词/品牌/预算；场景逻辑全部走 skills/plugins；每月同步上游，用上游 eval/ 评测集回归。

| 处置 | 模块（已核实路径） | 说明 |
|---|---|---|
| 保留 | core/agent、core/screen、core/safety、cap/phone、core/model、core/learn、core/proactive、core/mcp | 引擎原样，能力天花板不变 |
| 裁剪 | app/calls（AI 接打电话）、app/pocket、消费级语音/浏览器入口、companions/mika-feishu | 极客功能隐藏，代码保留便于后续按人群复活 |
| 修改 | core/prompt（PersonaPrompt/Prompts）→ 场景人设；core/agent/ModelRouter → 托管分档；core/agent/StopRules+UsageMeter → 预算熔断；applicationId 换名 | CLI 已支持 --package，换包名不破坏电脑连接 |
| 新增 | 建议卡片 UI（app/capsule 扩展）、AdvisorTurn、RemoteSync（core/remote 扩展）、托管登录、审计上传 | 见下文 |

关键改造点：

(1) 托管模型登录（用户不配 Key 的核心）
- 云端网关签发设备绑定短期令牌（JWT，24h，自动刷新），撤销即失效。
- Mika 自定义服务商指向网关（OpenAI 兼容），预置三个模型角色。core/model 零改动——上游本就支持自定义 provider + Key。
- 网关侧：主 Key 只存云端；按设备计量、限流、模型路由、峰谷调度。

(2) 建议卡片（顾问模式）
- 复用 screen/user/UserScreen 的屏幕采集，新增 AdvisorTurn：单次调用 core/model，提示词要求输出 JSON：
  {"understanding":"...","suggestions":[{"text":"...","tone":"..."}],"actions":["copy","send","extract"]}
- 渲染为结构化卡片而非聊天气泡；动作按钮接现有工具（复制/委托发送/抽取）。
- 修改点集中在 app/capsule + core/screen/user/UserScreenPrompt，不动 AgentLoop。

(3) 预算熔断
- UsageMeter 已记每轮用量；在 StopRules 加任务级预算：超 80% 提示降级，超 100% 停止执行并转顾问建议。
- 压缩触发点预置窗口 65%（上游「上下文与压缩」设置项，配置即可）。

(4) 场景包 = skills + plugins
- 技能：SKILL.md（上游 core/learn/skills 原生加载）。示例（回复顾问）：

```markdown
---
name: reply-advisor
description: 聊天界面回复建议。双击胶囊触发，输出3条候选回复。
---
1. 读取当前屏幕文本与截图，识别对话对象、最近5条消息、语气。
2. 按用户配置的语气/长度生成3条候选，禁止编造事实与承诺。
3. 输出结构化 JSON；涉及金额/发货时间等事实必须来自屏幕原文。
```

- 插件：plugins/<id>/manifest.json + scripts + skills（参考上游 mika.translate）。固定步骤写成沙箱确定性脚本，模型只做决策。
- 高频流程经 teach/replay 沉淀为 RouteReplay 重放，十几轮探索压到一两轮。

(5) 设备-云通道
- RemoteSync：设备主动 HTTPS/WSS 外连（无需公网 IP），负责配置下发、技能同步（签名 bundle）、审计上传（复用 core/run/record 脱敏导出）、订阅状态。
- 指挥手机：保留上游 MCP server（USB adb forward / Wi-Fi，Bearer 令牌）+ companions/mika CLI（task run/wait/status/export/download）。团队控制台经云端 MCP 桥调用。

## 3. 云端层（自建）

技术栈：Python FastAPI + PostgreSQL + Redis + 对象存储；模型网关基于 LiteLLM 二开（计量/限流/路由现成）。

服务拆分（MVP 单体起步，按模块拆包）：
- 账号计费：手机号登录、订阅、用量配额。
- 模型网关：短期令牌签发、按设备计量、模型分档路由、预算执行。
- 技能分发：场景包注册表、版本与签名、灰度下发。
- 审计存储：脱敏运行记录入库，团队控制台查询。
- 抽取表格：结构化结果存表、导出 xlsx、Webhook 写客户 CRM。
- MCP 桥：企微/飞书机器人推送、客户系统工具暴露给 Mika 的 MCP 客户端（core/cap/mcp 原生支持）。

## 4. 模型层配置（百炼）

| 角色 | 模型 | 用途 | 关键参数 |
|---|---|---|---|
| 主模型 | qwen3-max | 执行决策、工具调用 | 思考强度低档；压缩触发 65% |
| 看图 | qwen-vl-plus | 屏幕理解、顾问单次调用 | 截图降采样至长边 1280 |
| 轻量 | qwen-flash | 结局判断、记忆提取、意图 | 上游默认用主模型，必须改 |

接入：DashScope compatible-mode（https://dashscope.aliyuncs.com/compatible-mode/v1），网关统一代理。
成本目标：顾问 ≤0.02 元/次；执行 ≤0.3 元/任务（M0 实测校准，RouteReplay 命中后预期再降 50%+）。

## 5. 安全设计

- 主 Key 不出云端；设备令牌短期 + 设备绑定 + 可撤销。
- MCP Wi-Fi 模式默认关；令牌不下发日志；USB 优先。
- 审计上传前脱敏（手机号/金额/身份证掩码）；企业版数据不出域（私有部署网关+模型）。
- 执行安全沿用上游 safety/gate|guard|verify + takeover，不削弱。

## 6. 测试与质量

- 上游 eval/ 评测集 + 自建三场景验收集（每场景 ≥20 用例）。
- 机型白名单：M0 实测小米/华为/OPPO/vivo/荣耀主流机型，记录隐藏屏+无障碍+无线调试兼容性。
- CI：上游 GitHub Actions 基础上加场景回归；每次上游同步跑全量 eval。
- 灰度：技能包签名 + 灰度下发，坏包可回滚。

## 8. 技术风险与对策

| 风险 | 对策 |
|---|---|
| 国产 ROM 兼容性（隐藏屏/无障碍/无线调试） | M0 先测，机型白名单，USB 激活兜底 |
| 上游迭代快、接口漂移 | 薄 fork，月度同步 + eval 回归 |
| 微信风控 | 顾问模式兜底，不代发不群发 |
| 项目年轻、代码质量波动 | 验收集把关，关键路径加测试 |
| token 成本穿底 | 预算熔断 + 分档 + 重放 + 网关限额 |
| 应用商店上架难 | 官网/企业渠道分发，团队版 MDM 部署 |
