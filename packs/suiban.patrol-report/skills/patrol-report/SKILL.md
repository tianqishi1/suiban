# 定时巡检播报

你的任务：把「帮我盯着 X」变成一个可靠的定时任务，每次只花最少的轮次，**只报变化，不报废话**。

## 一、配置时问清四件事（一次性问完，别挤牙膏）

1. 盯什么：目标 App/页面/商品/关键词，让用户把目标页面打开给你看一次，记住入口路径。
2. 多久盯一次：默认每天 1 次；评价/差评类建议每 2–4 小时；用户说了算。
3. 什么算变化：价格任何变动 / 新差评（≤3 星）/ 库存低于阈值 / 新增评价。默认「有任何变化就报」。
4. 报到哪：Mika 通知（默认）；用户装了飞书/企微插件就推群；随办云端回传地址配了就 POST。

把这条巡检的入口路径、字段、阈值写进记忆/知识，后续每次巡检直接复用，不要重新探索。

## 二、每次巡检怎么跑（预算：≤5 轮模型调用）

1. 按记住的路径直达目标页（隐藏屏后台打开，不占用户前台）。走已学会的路线（重放），不要重新找按钮。
2. 读目标字段：控件树文本优先；价格/库存这类数字逐字符核对。
3. 与上次记录对比（记忆里存上次的值）：
   - 无变化 → 静默结束，只更新巡检时间，不打扰用户。
   - 有变化 → 生成播报。
4. 更新记忆里的当前值与时间。

## 三、播报格式

一条消息说清：盯的是什么、变了什么（旧值→新值）、什么时候发现的、建议动作（可选，一句话）。例：

> 【价格巡检】竞对 X 商品「无线耳机 Pro」降价：¥299 → ¥259（-13%），今天 14:00 发现。建议核对自家定价。

差评类播报附评价原文摘要（≤50 字）和订单号（如有）。

## 四、纪律

- 巡检是后台任务：不点购买、不发消息、不改任何设置，只读。
- 页面打不开/要登录/风控拦截：如实报「本次巡检失败+原因」，连续失败 3 次提醒用户检查，不要硬试。
- 每次巡检结束把用时和轮次记入任务小结，方便用户看成本。
