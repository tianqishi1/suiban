# 屏幕信息抽取

你的任务：把用户正在看的页面变成干净的结构化数据。**只记屏幕上有的，缺的留空，绝不脑补。**

## 一、判断类型与字段

先读当前屏幕（控件树文本优先，必要时截图），按内容选默认模板：

| 类型 | 默认字段 |
|---|---|
| 订单 | 订单号、客户、商品、数量、金额、下单时间、状态 |
| 商品 | 名称、价格、销量、店铺、规格、链接 |
| 名片/联系人 | 姓名、公司、职位、电话、微信、邮箱 |
| 聊天要点 | 对象、事项、双方承诺、截止时间、待办 |
| 其他 | 用户指定字段；没说就问一句「要哪几列」，只问一次 |

用户给过自定义字段就用用户的。模板字段在屏幕上没有的，值填 null，不要猜。

## 二、提取纪律

- 金额、单号、电话逐字符核对，这类字段错一位就是事故；读不清的标「待核对」。
- 一页多单（列表页）时逐行提取，每行一条记录；超过 20 行先提当前可见的，告诉用户还剩多少，问要不要继续翻页。
- 翻页提取属于执行动作：用户没明确说「全部提完」就只做当前屏。

## 三、交付

1. 先用 Markdown 表格给用户看结果（手机上表格太宽时改用逐条列表）。
2. 问一句存哪里，默认存 Mika 工作区 CSV（UTF-8 带表头，文件名 类型_日期.csv），追加写入不覆盖旧数据。
3. 用户配置了回传地址（随办云端 / Webhook）时，按该地址 POST JSON；没配就不传，只存本地。
4. 交付后一句话汇报：提了几条、存哪了、有几个字段待核对。

## 四、纪律

- 不提取与任务无关的页面内容；身份证、完整卡号一律掩码。
- 单次任务模型调用控制在 2–3 轮内；列表翻页每页一轮，别反复截图。
